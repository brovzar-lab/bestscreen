## Phase 2 — Automated Diagnostics

### 2.1 Visual capture — 3 viewports, both themes

Captured at 1440×900 (desktop), 768×1024 (tablet), 375×812 (mobile). Both light and dark captured on the desktop dashboard + editor; tablet/mobile in light only (theme is identical at smaller widths).

**Observations from the screenshots:**
- The Soft Print palette reads as intended in both themes: warm paper in light, warm charcoal (not slate) in dark.
- Rose CTA reads loud-and-only-once on the dashboard ("+ New screenplay").
- Streak heatmap now uses a sage gradient (correctly status, not brand).
- Project tile colors are warmed/desaturated (clay / plum) — no longer hot saturated reds.
- Editor preserves the manuscript paper feel; Courier Prime cleanly distinct from the Hanken Grotesk chrome.

### 2.2 Accessibility — axe-core 4.9.1

Five violation categories:

| Rule | Impact | Count | Notes |
|---|---|---|---|
| `color-contrast` | serious | 32 | Two root causes — see below |
| `label` | critical | 12 | `<input>` without `<label for>` (mainly title-page modal) — pre-existing |
| `select-name` | critical | 7 | `<select>` without an accessible name — pre-existing |
| `aria-dialog-name` | serious | 13 | `.modal-backdrop > .modal` blocks lack `aria-labelledby` — pre-existing |
| `region` | moderate | 16 | Content outside `<main>`/`<nav>`/etc. landmarks — pre-existing |

**Color-contrast root causes** (introduced or exposed by the redesign):
1. `--sp-text-3` (#8A8273) on `--sp-surface` (#FBF8F2) → 3.58:1 — fails AA (4.5:1). Used heavily for project card metadata, action buttons (Open/Rename/Export), section eyebrows.
2. `--sp-text-3` (#8A8273) on `--sp-bg` (#F1EBE0) → 3.20:1 — fails AA.
3. `#FFFFFF` on `--sp-rose` (#BC6A77) → 3.84:1 — fails AA for non-bold body text. Affects `+ New screenplay`, `.brand-mark`, all primary buttons.

The Soft Print spec explicitly states "Hold body text at ≥ 4.5:1 contrast even though the palette is intentionally gentle." The current `--sp-text-3` and `--sp-on-rose@rose` pairings don't meet this self-imposed rule.

### 3.2 Brand-vs-status color collisions found and resolved

The spec's #1 rule: **brand (rose) and status (sage/sand/clay) never share a hue**.

| # | Where it lived | Before | After | Rationale |
|---|---|---|---|---|
| 1 | `.save-state.saving .dot` | `var(--accent)` — rose | `var(--sp-sand)` | "Saving…" is an in-progress *status*, not the brand CTA. |
| 2 | `.btn.danger` (and `bsConfirm({danger:true})`) | inline `var(--accent)` — rose | `var(--sp-clay)` filled | Danger is *status*, not brand. Replaced the inline style with a real `.btn.danger` class. |
| 3 | `.dash-card-actions button.danger:hover` | `var(--accent-soft)/var(--accent)` | `var(--sp-clay-tint)/var(--sp-clay)` | Same — danger surfaces stay clay even on hover. |
| 4 | `.streak-l1..l4` (writing-streak heatmap) | gradient ending in `var(--accent)` (rose) | sage gradient (`tint → sage`) | A writing streak is a positive metric, not the brand CTA. |
| 5 | `.proof-mark.proof-unknown` (spellcheck underline) | hard-coded #c97f1a / #dba557 / #b46214 across themes | `var(--sp-sand)` + `var(--sp-sand-tint)` | "Unknown word" = Consider — sand. Unifies dark/light. |
| 6 | `#editor[data-pace="hot"/"warm"/"cool"]` (pace heatmap) | hard-coded #cf3a37 / #dfa116 / #4f8a3a | clay / sand / sage | Scene tension maps cleanly to the three SP semantic hues. |
| 7 | `.amb-url-status.error` (audio URL probe) | `var(--accent)` — rose | `var(--sp-clay)` | Error = status — clay. |
| 8 | `#fidelity-body .fid-status.ok/.warn` | hard-coded `rgba(75,140,75,…)` / `rgba(207,108,30,…)` | `--sp-sage-tint/sage` and `--sp-sand-tint/sand` | Tokenized for theming. |

### 3.3 Token utilization — the legacy alias strategy

Rather than rewriting ~200 call-sites of `var(--accent)`, `var(--ink)`, etc., the redesign **redefines the legacy tokens as aliases** that point at Soft Print tokens (`--accent → --sp-rose`, `--ink → --sp-text`, etc.). This keeps the existing 3,887-line stylesheet working *unchanged* under the new palette and lets dark mode flip via a single `[data-theme="dark"]` block.

Trade-off: any future contributor who reads `var(--accent)` won't see "rose" directly — they have to follow the alias. Acceptable while the rest of the file remains.

### 3.4 What's still off-system

- **Title-page modal "Theme" field** (`#tp-theme`) is a screenplay's *thematic* theme (story theme), not visual theme — kept as a plain text input by design.
- **Categorical palettes** for scene tags, beat cards, revisions, and project covers: warmed to fit Soft Print but still explicit hex (user-choosable colors). Not status.
- **Status-bar type pills** (`.status .pill[data-type="…"]`): now token-driven via the categorical `--color-*` palette, but they assign one of {amber, blue, purple, red, green} to each line-type. Categorical, not status — fine, but could be unified to a single neutral pill + a type-letter for less color noise.

## IMMEDIATELY (this sprint)

### 1. Fix `--sp-text-3` contrast — the biggest spec violation
- **Category:** a11y / design
- **Impact:** Critical (spec rule #1 violated, 32 axe failures, screen reader users get caption-tier text everywhere)
- **Effort:** S
- **Files:** `styles.css` (token block, ~line 35-37)
- **Fix:** Two-line change. Update `--sp-text-3` to a darker warm taupe that hits 4.5:1 on `--sp-surface`:
  ```css
  /* Was */ --sp-text-3: #8A8273;   /* 3.58:1 on --sp-surface */
  /* Now */ --sp-text-3: #6E6757;   /* 4.55:1 on --sp-surface, still recognisably "muted" */
  ```
  Dark-mode equivalent: bump `--sp-text-3` from `#7D7464` to `#8E8472` (currently fails dark-bg contrast too).

### 2. Fix `#fff` on `--sp-rose` button contrast
- **Category:** a11y
- **Impact:** High (every primary button — `+ New screenplay`, the brand mark, dialogs — fails AA)
- **Effort:** S
- **Files:** `styles.css` (`:root` block)
- **Fix:** Pick one of:
  - **A.** Darken the rose-fill: redefine `--sp-rose` to `#A1505D` (currently the *strong* rose, 5.4:1 vs #fff). Keep `--sp-rose-strong` as today.
  - **B.** Make button text bold (font-weight ≥600) and ≥14px — that qualifies as "large" under WCAG and the existing 3.84:1 then passes. Less invasive but only fixes buttons.
  - Recommend **A** — keeps the rule simple ("rose is always 4.5:1 on white").

### 3. Add `aria-labelledby` to modals
- **Category:** a11y
- **Impact:** Serious (13 dialogs unnamed)
- **Effort:** S
- **Files:** `index.html` (every `.modal[role="dialog"]`), `app.js` (the inline `modalConfirm` / `modalPrompt`)
- **Fix:** Modals already have an `<h2>`-style title; add `id="…-title"` and `aria-labelledby="…-title"` on the wrapper. For the inline confirm/prompt helpers, set `aria-labelledby` to the dynamic `<h2>`'s id (generate one per call).

### 4. Add `<label for>` / `aria-label` to title-page inputs and selects
- **Category:** a11y
- **Impact:** Critical (12 inputs + 7 selects unnamed)
- **Effort:** S
- **Files:** `index.html` (`#modal-titlepage` form-rows — they already have `<label>`s but use `<label>Theme</label><input…>` instead of `<label for>` pairing)
- **Fix:** Either add `for="…"` to existing labels or wrap input in label. Same treatment for `<select>`s in inspector and bible.
